# MedQA-Bench: Multi-Provider LLM Evaluation Pipeline with MLflow

An end-to-end MLflow pipeline that benchmarks free-tier LLMs on medical question
answering (USMLE-style), tracks every prompt–model–parameter combination as a
versioned experiment, and promotes the best configuration to a model registry.

---

## How This Differs from `MLOps/Labs/Experiment_Tracking_Labs/Mlflow_Labs/Lab2 (Wine Quality)`

| Aspect | Lab 2 | This Project |
|--------|-------|--------------|
| **Task** | Wine quality prediction (tabular classification) | Medical QA (LLM text generation) |
| **Model** | Scikit-learn RandomForestClassifier (trained weights) | API-based LLMs (OpenAI, Anthropic, Google, Groq) — no local weights |
| **Logged artifact** | Pickled sklearn model | Prompt/config YAML (provider + model_id + strategy) |
| **Experimentation** | Single model, manual registration | Grid: provider × model × prompt strategy; automated best-run selection |
| **Selection** | Manual `mlflow.register_model` → transition to Production | Composite score (accuracy + latency + judge) → `register_best` promotes winner |
| **Serving** | `mlflow models serve` with serialized model | `PythonModel` that calls LLM APIs at predict time |

Lab 2 follows the classic MLflow flow: train → log model → register → serve. This project treats the *configuration* (which LLM + which prompt) as the model, and uses MLflow to version, compare, and promote the best configuration to the registry.

## 1. Problem Statement

Given a medical QA dataset with ground-truth answers, find the best-performing
LLM + prompt strategy combination across multiple providers — treating the full
configuration (provider, model version, system prompt, decoding params, few-shot
examples) as the “model artifact” rather than weights.

---

## 2. Dataset

**MedQA-USMLE 4-Options**

- Source: `GBaker/MedQA-USMLE-4-options` on HuggingFace
- 12,723 USMLE-style multiple choice questions (4 options each)
- Fields: `question`, `options` (dict with A/B/C/D), `answer` (correct letter)
- License: Public research use
- We sample 200 questions for eval (cost control), ideally stratified by difficulty

Why this dataset:

- Has unambiguous ground truth (single correct letter) → enables exact-match scoring
- Domain complexity forces models to reason, not just pattern match
- Medical QA is directly relevant to pharma/clinical settings
- Well‑studied benchmark — lets you compare your results against published numbers

---

## 3. Models Under Evaluation

| Provider  | Model ID                  | Free Tier Access                   |
|----------|---------------------------|------------------------------------|
| OpenAI   | `gpt-4o-mini`             | Free credits on new accounts       |
| Anthropic| `claude-3-haiku-20240307` | Free API credits                   |
| Google   | `gemini-3-flash-preview`  | 250 RPD free via AI Studio API key |
| Groq     | `llama-3.1-70b-versatile` | Free tier, 30 req/min              |

All providers expose a chat-completions style interface (Groq natively,
Gemini via `google-genai`, Anthropic via its SDK). We unify them behind a single
`call_model()` abstraction.

## 4. Prompt Strategies

Each strategy is a YAML config file — this **is** the artifact we version.

See the files in `configs/`:

- `zero_shot_direct.yaml`
- `chain_of_thought.yaml`
- `few_shot_3.yaml`

```text

├── README.md

├── configs/
│   ├── models.yaml

│   ├── prompt_builder.py         # Loads YAML config, formats prompts
│   ├── experiment_runner.py      # Main loop: model × strategy → MLflow runs

│   ├── compare_runs.py           # Pull runs, build comparison, visualize
│   ├── register_best.py          # Wrap + register winner in Model Registry

├── notebooks/
│   └── analysis.ipynb            # Optional interactive analysis
└── mlruns/                       # Auto-generated by MLflow (local tracking)
```

## 8. Usage Overview

1. **Prepare data**

   ```bash
   cd MedQA_Bench
   python -m data.prepare_dataset
   ```

2. **Run experiments**:

   ```bash
   python -m src.experiment_runner
   ```

3. **Analyze runs**

   ```bash
   python -m src.compare_runs
   ```

4. **Register best configuration as a model**

   ```bash
   python -m src.register_best
   ```
